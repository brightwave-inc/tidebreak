# N. Decision Title

- Status: Proposed | Accepted | Superseded | Rejected
- Date: YYYY-MM-DD
- Owners: name or area
- Related: other records, docs, or migrations this one depends on
- Supersedes: record number, if any

## Context

The concrete problem, and the forces acting on it. Separate what is true today
from what is being assumed — a reader a year from now cannot tell them apart
from the outside. Link the code, docs, or measurements that establish the facts.

## Decision

The chosen behavior and its boundaries, stated precisely enough to implement
and to test against. Say what is deliberately excluded as well as what is
included.

## Alternatives Considered

The viable alternatives and why each was not chosen. Include "do nothing" when
it is a real option. A record that lists only the chosen design cannot stop the
same argument being reopened six months later.

## Consequences

What this costs: migration work, operational and security impact, constraints
it places on future changes, and anything it makes harder. End with what would
cause this decision to be revisited.

## Validation

The tests, checks, or observations that would show the decision holds — and, in
particular, any case a plausible wrong implementation would still pass.
